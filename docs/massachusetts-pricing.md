# Massachusetts grocery estimates and actual spending

The user selected Massachusetts on November 3, 2026. The initial reference catalog uses the Northeast region, which includes Massachusetts; these are regional averages, not Massachusetts store quotes.

## Sources and limits

The initial dataset is [BLS Northeast average retail food prices](https://www.bls.gov/regions/mid-atlantic/data/averageretailfoodandenergyprices_usandnortheast_table.htm), September 2026, retrieved November 3, 2026. Nine narrowly matched food references are recorded in [northeast-price-references.json](../packages/contracts/src/northeast-price-references.json). Missing Northeast observations are left missing; national values are not silently substituted. Unmatched names, incompatible ingredient forms and unknown amounts stay unpriced rather than receiving a guessed match.

BLS publishes food averages for standard measurement units and excludes sales tax. A standard pound is not proof that a product is sold in a one-pound package. See [BLS methodology](https://www.bls.gov/cpi/factsheets/average-prices.htm). The initial references therefore produce quantity-based priced subtotals with unknown checkout packaging. They cannot produce a complete package checkout estimate by themselves. The engine supports rounded-up package costs only for references explicitly identified as verified packages; automated tests cover that separate calculation.

Each reference preserves source URL, observation month, region, currency, price basis and confidence. Store is null because no store was observed. References are labeled low confidence for individual shopping estimates. They expire from calculation 120 days after their observation month ends. Future observations are not used. No prices are generated by AI.

All undeleted weekly grocery items count, including already checked items, manual purchases, regular purchases and household goods. Unmatched household purchases remain explicitly unpriced. No density or count-to-weight conversion is guessed. If no item can be priced, the priced subtotal is unavailable, rather than $0. Missing prices, verified package sizes, tax or fees keep the total incomplete. An incomplete subtotal never produces a claim that checkout fits under budget.

The panel identifies the requested region, actual reference geography and observation month and links to the official source. It exposes priced lines and reasons for unpriced lines. When known priced amounts exceed the budget, it reports the difference; automatic or approval-based cheaper meal suggestions remain unfinished.

## Actual weekly spending

Actual spending is one editable total for the selected week, including all shopping trips, tax, fees and non-food purchases. It is separate from the estimate and weekly ceiling. Blank means not entered; $0 is an explicit saved value. Optional tax and fee fields apply to the estimate, not to the actual total. The app does not infer Massachusetts tax treatment or store delivery charges.

Saving requires a connection. All three totals use integer cents between $0 and $10,000. Retries retain the same request key; stale revisions are rejected and unsaved entries are retained. Background estimate refreshes keep dirty entries and do not rebase them silently onto another device's edits. Reload spending replaces the form with saved values. Budget reset changes the ceiling without removing the actual total or grocery checkmarks.

## Activate account-backed totals

The regional estimate works with the updated API. Saving totals requires the additive [weekly checkout migration](../supabase/migrations/202611030002_weekly_checkout.sql). It creates a private weekly totals table and two scoped functions. It preserves kitchen, recipes, plans, grocery lists and budget ceilings. Do not rerun setup, imports or the previous kitchen migration for this feature.

1. In the development Supabase SQL Editor, run only `supabase/migrations/202611030002_weekly_checkout.sql`.
2. Refresh the app and open Groceries. The actual weekly total and optional tax/fee inputs should appear.
3. Enter a real known weekly total when available. Blank remains different from zero. Navigate between weeks and confirm each total is independent.

Hosted activation is confirmed November 3 by user-reported SQL success and `npm run check:checkout -w @meal/api`, which verifies the read function exists and denies anonymous access. The user confirmed authenticated real-account actual spending saves and survives refresh. Local PostgreSQL tests cover ownership, blank/zero, week isolation, revisions, rollback and idempotency. Browser tests cover a failed save with preserved entries/key, later success, separate estimates, budget changes/reset, checked-item inclusion and independent weeks.

## Maintenance

Review the official Northeast table monthly. Update only observed regional values, observation period and retrieval date. Preserve the exact product definition, narrow aliases and measurement basis. Do not fill blank cells, apply an invented Massachusetts markup, treat unit averages as package sizes, or invent confidence ranges. Retain old versions in source history for reproducibility. Broader reference coverage and a verified store/package integration remain future work.
